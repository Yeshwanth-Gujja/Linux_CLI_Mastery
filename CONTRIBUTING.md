# Contributing

Thank you for contributing to Linux CLI Mastery.

## Before You Start

- Read the existing notes and preserve their terminology and structure.
- Keep additions practical and beginner-friendly without deleting important technical detail.
- Prefer explanations that connect commands to a mental model.
- Verify commands, Markdown links, examples, and diagrams before opening a pull request.
- Do not include destructive commands without a clear warning and safe context.

## Workflow

1. Fork the repository.
2. Create a focused branch.
3. Make the change and review the diff.
4. Test commands/examples in a safe Linux environment.
5. Commit with a clear imperative message.
6. Push the branch and open a pull request.

## Pull Requests

Include what changed, why it is useful, which notes/examples are affected, and which commands/examples were tested.
